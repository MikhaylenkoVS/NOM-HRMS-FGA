# Design: DOC-01 — User guide для химика

## Подход
Создать линейный Markdown-документ `docs/user_guide.md`, ориентированный на первый успешный запуск. Принцип: сначала минимальный воспроизводимый анализ, затем объяснение параметров и интерпретации.

Каждый раздел должен отвечать на вопросы: что подготовить, что нажать, что ожидать, как интерпретировать результат и что делать при ошибке.

## Структура
```text
1. Назначение приложения
2. Что потребуется
3. Установка и запуск
4. Подготовка CSV
5. Первый анализ трёх спектров
6. Интерпретация результатов
7. Presets
8. Частые ошибки
9. Что приложить к сообщению об ошибке
10. Дополнительные материалы
```

## Стиль
- Писать по-русски простым техническим языком.
- Английские названия UI приводить точно, как в приложении, с кратким русским пояснением.
- Использовать короткие нумерованные действия.
- Выделять важные ограничения.
- Не использовать абсолютные пути и не описывать внутреннюю архитектуру.
- Не добавлять screenshots без отдельной проверки их соответствия release target.

## CSV
CSV-раздел основывать только на фактическом reader-коде и тестовых файлах. Явно описать обязательные mass/mz и intensity поля, допустимые дополнительные колонки, разделитель, десятичную запись, пропуски, нечисловые значения, дубликаты и минимальные требования к данным. Если есть несколько вариантов, показать минимальный и рекомендуемый.

## Первый анализ
1. Запуск приложения.
2. Загрузка трёх поддерживаемых CSV.
3. Выбор preset или параметров.
4. Запуск обработки.
5. Проверка таблицы и графиков.
6. Указание признаков, требующих дополнительной проверки.

## Scientific safety
Явно указать, что formula assignment не доказывает структуру, preset является стартовой точкой, VK-диаграмма не является самостоятельным структурным доказательством, а для публикации нужно фиксировать версию приложения, preset и параметры обработки.

## Навигация
После готовности добавить краткую ссылку на user guide в `README.md` или `docs/README.md`, без дублирования полного текста.
