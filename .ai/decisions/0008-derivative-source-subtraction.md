# ADR 0008: шумоподавление дериватизатов и вычитание исходного спектра

* Статус: принято; с 17.10 включено по умолчанию вместе с ужесточением окна (см. ADR-0009: точность прежде полноты)
* Дата: 2026-10-17
* Затрагивает: `src/core/spectrum/_overlap.py` (новый), `src/core/pipeline/_stages.py`,
  `src/core/pipeline/_run.py`, `src/configs/pipeline.json`, GUI, CLI

## Контекст

В производных спектрах (CD3 / CD3CO) присутствуют сигналы непрореагировавших
соединений — те же m/z, что и в исходном спектре. Они не являются продуктами
дериватизации, но попадают в поиск серий: соединение может «найти» ложную ступень
`m0 + n·Δ`, если рядом оказался чужой пик, из-за чего `N_COOH` / `N_OH` завышаются.

Кроме того, ранее дериватизаты по умолчанию не шумоподавлялись (пики продуктов
низкоинтенсивные), поэтому в поиске серий участвовал и приборный шум.

## Решение

1. Новый модуль `_overlap.subtract_matching_peaks(deriv, src, ppm_tol, one_to_one=True)`:
   удаляет из производного спектра пики, совпадающие по m/z с пиками исходника.
   **Модель «один к одному»:** каждый пик исходника вычитает не более одного
   (ближайшего по массе) пика дериватизата. Пары выбираются жадно по возрастанию
   отклонения в ppm, каждая используется один раз, поэтому один пик дериватизата
   не может быть вычтен дважды. Обоснование: если пик исходника накладывается
   на пик дериватизата, такой пик и так не подтверждает дериватизацию, значит
   потенциальные дериватизаты в этой модели не теряются.
   **Интенсивности не сравниваются** — совпадение только по массе в ppm-окне
   (поиск кандидатов — `searchsorted`, O(N log M)). Порядок строк сохраняется.
2. В пайплайне — опция `subtract_source` (+ `subtract_ppm`, по умолчанию 5 ppm):
   применяется после шумоподавления обоих спектров и до поиска серий.
3. Опция `denoise_derivatives` остаётся отдельной: её можно включить без вычитания.
4. Счётчики `dmet_overlap_removed` / `dacet_overlap_removed` добавлены в
   `PipelineStats` и печатаются в лог.

## Почему по умолчанию выключено

Модель «один к одному» снимает основное возражение (один пик не вычитается
несколько раз), но остаётся вопрос калибровки окна: при 5 ppm пик исходника
может совпасть с настоящей ступенью другого соединения. Поэтому решение
включается после сравнения на реальных сетах (F16, затем SRFA/F14) по числу
серий и сумме `N_COOH` / `N_OH`; при подтверждении — станет умолчанием.

## Последствия

* Меньше пиков в производных спектрах → быстрее поиск серий.
* Меньше ложных ступеней → ниже завышение функциональных групп.
* Требуется контроль: число «потерянных» настоящих серий на эталонных наборах.
