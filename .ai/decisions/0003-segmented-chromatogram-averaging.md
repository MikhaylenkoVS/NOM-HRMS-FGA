# ADR-0003: Сегментное усреднение хроматограмм с сохранением RT исходных пиков

- **Status:** proposed
- **Date:** 2026-10-12
- **Owners:** deepcode (требует утверждения человеком)
- **Related task:** chrom-01-segmented-averaging
- **Related issue/PR:** none
- **Supersedes:** none
- **Superseded by:** none

## Context

Текущий пайплайн усредняет RAW/mzML по одному RT-окну, RT теряется,
поиск серий исходный↔дериватизованный выполняется только по m/z.
Пользователю нужен сегментный анализ: разбить RT-диапазон на отрезки
(по умолчанию 2 мин), усреднять и шумоподавлять внутри отрезка,
сохранять RT для исходных пиков, а производные искать по всем отрезкам
дериватизованных спектров (RT производных не сохраняется и не
сопоставляется).

## Decision

1. RT-диапазон разбивается на настраиваемые отрезки `(start, end)`
   шириной `segment_width` (по умолчанию 2.0 мин).
2. Усреднение и шумоподавление выполняются независимо внутри каждого
   отрезка.
3. Исходные пики сохраняют RT своего отрезка (`rt_start`, `rt_end`);
   для CSV/JSON/XLSX без RT используется один сегмент с `rt_start=None`,
   `rt_end=None`.
4. Дериватизованные сегменты усредняются по тем же окнам, но для поиска
   серий объединяются в один спектр без RT — производное не обязано иметь
   то же время удерживания, сегменты между файлами не сопоставляются.
5. Сегментный режим доступен через Python API
   (`run_pipeline_segmented`), CLI (`--segment-width`, `--rt-min`,
   `--rt-max`) и GUI (галочка + ширина отрезка).

## Alternatives considered

| Alternative | Pros | Cons | Reason rejected |
|------------|------|------|-----------------|
| Сопоставлять сегменты 1:1 между файлами | просто | теряются производные с другим RT | противоречит требованию пользователя |
| Хранить RT и для производных | полная информация | усложняет результат; пользователю не нужно | пользователь явно отказался |
| Хроматографический пик-пикинг (EIC) | точнее по физике | новый алгоритм, больше рисков | отложено; текущая задача — сегментное усреднение |

## Consequences

### Positive

- Исходные пики получают временную привязку, производные ищутся по всем
  сегментам — устойчивость к сдвигу RT между образцами.

### Negative

- Один и тот же исходный m/z может появиться в нескольких сегментах как
  отдельные записи (это ожидаемое поведение).

### Risks

- Пик на границе отрезков разделяется. Митигация: настраиваемая ширина
  отрезка; в будущем — перекрытие окон.

## Validation and rollback

- Референс-эквивалентность: на CSV set_01 сегментный режим (один сегмент)
  должен давать те же mass/brutto/N_COOH/N_OH, что и обычный
  `run_pipeline`.
- Юнит-тесты `build_rt_segments` и `aggregate_scan_lists`.
- Rollback: `git revert` коммитов ветки
  `feat/chrom-01-segmented-averaging` (см. `rollback_plan.md`).

## Scientific/reproducibility impact

- Обычный `run_pipeline` не меняется; сегментный режим — отдельная
  функция. На CSV-данных результаты совпадают (один сегмент).
