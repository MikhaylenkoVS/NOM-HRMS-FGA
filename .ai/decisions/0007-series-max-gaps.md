# ADR 0007: не более одного пропуска в серии (по умолчанию)

* Статус: принято
* Дата: 2026-10-16
* Затрагивает: `src/core/spectrum/_series.py`, `src/core/pipeline/`,
  `src/configs/pipeline.json`, GUI, CLI

## Контекст

Поиск гомологических серий дериватизации (`find_series`) восстанавливает число
функциональных групп по числу найденных ступеней ``m0 + n·Δ``. До этого решения
ограничивалось только число **подряд** пропущенных ступеней
(``max_consecutive_misses = 3``), а суммарное число пропусков внутри серии не
ограничивалось ничем: серия вида «1, 3, 5, 7» с тремя пропусками принималась как
семь групп. На реальных данных (Fulvagra, SRFA) это давало заметное число серий с
внутренними пропусками («ВНИМАНИЕ: внутренних пропусков в сериях: 649» на F16).

## Решение

1. Новый параметр ``max_gaps`` (целое, по умолчанию **1**) — максимальное число
   пропущенных ступеней внутри серии. ``0`` — пропуски запрещены.
2. При исчерпании бюджета (``gaps > max_gaps``) серия **обрывается на последней
   найденной ступени**, поэтому инвариант ``len(missing) <= max_gaps`` выполняется
   всегда, а уже надёжно найденные ступени не теряются.
3. Параметр доступен пользователю: поле «Пропусков в серии (0 = без пропусков)»
   в GUI, ключ ``--max-gaps N`` в CLI, ``run_pipeline_defaults.max_gaps`` в
   `pipeline.json`.
4. ``allow_gaps`` сохранён как устаревший синоним: ``False`` эквивалентно
   ``max_gaps=0``; ``True`` больше не означает «пропусков сколько угодно» —
   число пропусков всегда ограничено ``max_gaps``.

## Последствия

* Серии с двумя и более пропусками больше не завышают ``N_COOH`` / ``N_OH``.
* На эталонных наборах поведение проверяется тестами `tests/unit/test_find_series.py`
  (класс `TestMaxGaps`): 0/1/2 пропуска, синоним ``allow_gaps=False``, инвариант
  бюджета.
* Если для каких-то образцов потребуется более мягкое правило, пользователь
  задаёт ``max_gaps`` сам (например, ``--max-gaps 2``); менять код не нужно.
