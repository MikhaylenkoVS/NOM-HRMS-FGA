# ADR-0004: Расширение набора элементов (S, P, галогены) и изотопный паттерн в назначении формул

- **Status:** accepted
- **Date:** 2026-10-13
- **Owners:** MikhaylenkoVS
- **Related task:** elem-01-halogens-isotopes
- **Related issue/PR:** PR в `main` (см. `.ai/tasks/active/elem-01-halogens-isotopes/task.json`)
- **Supersedes:** none
- **Superseded by:** none

## Context

Алгоритм назначения брутто-формул (`src/core/spectrum/_assign.py`) перебирал только
CHNO-формулы в узком боксе (C 1–50, H 4–100, O 0–25, N 0–10) с ограничениями
H/C ≤ 3, O/C ≤ 1.2, N/C ≤ 1.0, DBE ≤ 30. Из-за этого:

* пики S-, P- и галоген-содержащих соединений либо не получали формулы, либо
  «объяснялись» химически неверными CHNO-формулами;
* изотопный контроль был сведён к эмпирической формуле Бейнона для M+1
  (C 1.1 %, H 0.015 %, N 0.37 %, O 0.04 %) — без M+2, без S/Cl/Br и без учёта
  изотопных вариантов;
* манифест сжатой базы формул (`data/formula_db/chposp_1000_zstd9_v2`) уже
  содержал CHNOSP (79 576 593 формулы, запись uint32 `C|N|O|S|P`, H
  восстанавливается по границам блоков), но **сама база в пайплайне не
  использовалась** — назначение шло перебором.

## Decision

1. **Элементы.** Набор элементов и их диапазоны переведены в конфиг
   (`configs/constants/formula_search.json`): C, H, O, N, S, P, F, Cl, Br, I.
   Массы элементов добавлены в `configs/chemistry.json`.
2. **Изотопы.** Добавлена таблица изотопов (масса + природная распространённость)
   в `configs/constants/isotope.json` и модуль
   `src/core/spectrum/_isotopes.py`: теоретический паттерн M/M+1/M+2
   (свёртка, корректно для Cl/Br/S), изотопные варианты
   (`13C`, `2H`, `37Cl`, `34S`, `81Br`, …) и `find_isotope_variants()`
   для сопоставления вариантов с наблюдаемыми пиками.
3. **Скоринг.** Введены штрафы **по атомам** (S 1.0, P 1.5, галоген 1.5):
   без изотопного подтверждения такая формула проигрывает CHNO-варианту в
   пределах ppm-окна. Если M+2 совпадает с теоретическим паттерном, начисляется
   `bonus_isotope_m2` — тогда S/Cl/Br-формула может выиграть. Это и есть
   проверка «нестандартного изотопа» через паттерн.
4. **Поиск.** Вместо генерации всех формул до 1000 Да — генерация **под каждый
   пик** в узком окне (±ppm, кэш по сетке 0.001 Да) с отсечением по массе,
   DBE, чётности (правило Льюиса) и лимитам отношений элемент/C.
5. **Исправление ошибки.** В композитном скоре DBE считался как
   `1 + C − H/2 + O/2` (использовался кислород вместо азота) — исправлено на
   `(2C + 2 + N + P − H − X)/2`.

## Alternatives considered

| Alternative | Pros | Cons | Reason rejected |
|------------|------|------|-----------------|
| Оставить CHNO | Ничего не меняется, быстро | Теряется S/P/галоген-химия | Не решает задачу |
| Полный перебор всех элементов «на широко» (X/C ≤ 0.5) | Максимальный охват | Замерено: 21 114 кандидатов и **3.9 с на один пик** при m/z 800; для 20 000 пиков — часы | Неприемлемо по времени |
| Дублировать поиск по сжатой базе формул (этап 4) | Микросекунды на пик, широкая химия | Нужен новый формат записи (uint32 занят полностью) и пересборка на сотни миллионов формул | Отложено отдельной задачей (см. Consequences) |
| Расширить только CHNO → CHNOSP без галогенов | Дешевле | Не покрывает галогены | Частичное решение |

## Consequences

**Положительные:**
* Пики S/P/галоген-содержащих соединений получают формулы; на set_01 назначено
  226 формул из 316 пиков (ранее 119 строк результата).
* Изотопный паттерн считается по таблице для всех элементов, включая M+2,
  который для Cl/Br/S является решающим.
* Появился API для изотопных вариантов — основа для отчёта по изотопам.

**Ограничения и риски:**
* Время назначения выросло: set_01 (316 пиков) — ~66 с (было ~2 с). Причина —
  перебор в Python; для спектров с десятками тысяч пиков нужен этап 4.
* Лимиты отношений S/C ≤ 0.2, P/C ≤ 0.1, X/C ≤ 0.1 заданы умеренными
  (обосновано замерами, зафиксировано в `_ratio_limits_note` в конфиге).
  По-настоящему широкие диапазоны возможны только после этапа 4.
* Формулы с галогенами/S/P без изотопного подтверждения проигрывают CHNO —
  это сознательный консервативный выбор (снижение ложных назначений).

**Follow-up (обязательный):**
* Этап 4: новая версия сжатой базы (uint64: C, N, O, S, P + F, Cl, Br, I),
  пересборка, обновление манифеста и **подключение базы к назначению** вместо
  перебора — обязательное условие для широких диапазонов элементов.
