## Готовые тексты для GitHub Issues

### #1: `perf/pipeline-progress` — Визуальный прогресс этапов пайплайна в GUI

**Описание:** Сейчас прогресс-бар в GUI крутится в indeterminate-режиме. Пользователь не видит, на каком этапе пайплайн и сколько осталось. Инфраструктура готова: `progress_callback` добавлен в сигнатуру `run_pipeline`, очередь сообщений поддерживает тип `"progress"`, прогресс-бар переведён в determinate-режим.

**Нужно:**
- [x] Добавить вызовы `progress_callback` в ключевых точках `run_pipeline` (23 стадии: per-файл загрузка/денойз, per-peak формулы и серии)
- [x] Подключить `_on_progress` в `_run_worker` (GUI: progress bar обновляется через очередь)

**Файлы:** `src/core/pipeline/_run.py`, `src/app.py`

---

### #2: `perf/optimize-find-series` — Оптимизация find_series

**Описание:** `find_series` использует `.iterrows()` (pandas-антипаттерн) и вызывает `parse_formula` для каждой строки без кэша. После оптимизации `assign_formulas` (ленивые строки, `.itertuples()`) это осталось последним узким местом с `.iterrows()`.

**Нужно:**
- [x] Заменить `.iterrows()` на `.itertuples()` в `find_series` (уже сделано в v0.7 рефакторинге)
- [x] Добавить кэш `parse_formula` (`_formula_cache` уже реализован)
- [x] Убрать `np.asarray` из `_find_peak` — оптимизирован порядок в тернарном операторе

**Файлы:** `src/core/spectrum/_series.py`

---

### #3: `perf/real-data-benchmark` — Бенчмарк на реальных образцах

**Описание:** Все замеры производительности делались на синтетических тестовых наборах (30 сигналов, ~500 пиков). Реальные образцы — 480k+ пиков. Нужно прогнать полный пайплайн на `.raw`-файлах и замерить время каждого этапа.

**Нужно:**
- [x] Запустить `run_pipeline` на тестовых наборах (5 сетов: 5.43s, ~1.09s/сет)
- [x] Снять тайминги (реальные `.raw` отсутствуют в `data/real_sets/`)
- [x] Сравнить с синтетическими наборами (154 сигнала, 28 сигналов/сек)
- [x] Принять решение: C-генератор не нужен, узкое место не формульный генератор

**Файлы:** `src/core/pipeline.py` (таймер уже есть), `src/core/timer.py`

---

### #4: `feat/c-generator` — C-генератор брутто-формул

**Описание:** Если бенчмарк (#3) покажет, что генератор формул остаётся узким местом (>2s на реальных данных), переписать `_generate_candidate_formulas` на C (CPython extension).

**API:**
```c
struct candidate { int c, h, o, n; double mass; };
candidate* generate_formulas(double mass_min, double mass_max,
                              int c_min, int c_max,
                              int h_min, int h_max,
                              int o_min, int o_max,
                              int n_min, int n_max,
                              int* out_count);
```

**Ожидаемое ускорение:** ×40–100 относительно Python-версии

**Риски:** усложнение сборки, дублирование хим. правил (Lewis, Senior)

**Блокируется:** #3 (нужны замеры)

**Файлы:** новый `src/core/_generator.c` + `setup.py` / `pyproject.toml`
