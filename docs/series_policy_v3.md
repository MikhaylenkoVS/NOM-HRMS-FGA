# Политика серий v3 (зафиксирована 2026-10-21)

Документ фиксирует решения по фильтрам и статусам после разбора
`reliability_policy_f16`. Композитные режимы (`strict hard`, `soft`,
`margin hard`) больше не используются как отдельные сущности.

## 1. Статусы и confidence

- `reliable` — шаг без наложений:
  - `n_deriv ≥ 1`, `n_src = 0`; или
  - `n_deriv ≥ 1`, `n_src = M ≥ 1`, profile разрешает `≥ 1 + M`.
- `ambiguous` — шаг с наложением/неразрешённым профилем, а также шаг с
  O-превышением, изотопным штрафом или другим штрафом.
- Profile-разрешение подключено: для `n_src > 0` читаются 3 RAW-скана
  дериватизата, в объединённом окне считаются разрешённые пики; если их
  `>= 1 + n_src`, source-штраф снимается и шаг может стать reliable.
- `confidence` считается **только для ambiguous-шагов после последнего
  reliable**. Формула: `confidence = 100 − min(100, сумма штрафов)`.
- Пока persistence, profile и профиль интенсивностей **не** переводят
  reliable в ambiguous. Это зарезервировано на следующий этап: при мягких
  нарушениях они будут добавлять штраф и переводить шаг в ambiguous.

## 2. Штрафы

Веса стартовые, вынесены в конфиг; сумма ограничена 100.

| Причина | Макс. штраф | Масштабирование |
|---|---:|---|
| наложение на исходник | 30 | по доле неразрешённых пиков |
| плохое разрешение | 25 | по `1 − k_obs/(1+n_src)` |
| несколько дериватизатов в окне | 20 | по `N−1` |
| превышение O-лимита | 40 | по числу лишних шагов |
| пропуск шага | 15/шаг, cap 45 | по числу пропусков |
| конфликт без предыдущей ступени | 30 | фиксированный |
| конфликт-наложение | 10 | фиксированный |
| профиль пика | 10 | по S/N и FWHM |
| persistence < 80 % | 10 | линейно от 0.8 до 0 |
| профиль интенсивностей | 5 | по скачку/корреляции |
| изотопный паттерн | 30 | по относительному отклонению |

## 3. O-лимит

- `max_length` — пользовательская максимальная длина поиска.
- Поиск **не** ограничивается кислородом: можно найти шаги выше O-лимита.
- `O_limit(CD3) = O // 2`, `O_limit(CD3CO) = O`.
- Шаг `n > O_limit` не может быть reliable; он попадает в ambiguous с
  причиной «превышение допустимой длины по количеству атомов кислорода».
- Отчёт: `confirmed(ambiguous)`, например `3(5)`; причины — по каждой
  степени.
- `O_limit = 0` допустим (например, CD3 при O = 1).

## 4. Пропуски и первая ступень

- `max_gaps = 0` по умолчанию; пользователь может разрешить N пропусков.
- `require_first_step = False` по умолчанию; пользователь может включить.
- Если первые три ступени отсутствуют, длина = 0 **всегда**, независимо от
  `require_first_step`.
- `min_series_length` удалён как параметр; внутреннее требование — хотя бы
  один найденный шаг.

## 5. Что удалено

- прямое вычитание исходника (`subtract_source`, `subtract_ppm`);
- `trim_to_confirmed_last`;
- `drop_ambiguous`;
- persistence как отдельный статус в `add_status`;
- `min_series_length` из API/GUI/CLI.

## 6. Изотопный фильтр

- Применяется и в assign, и при поиске серий.
- Пользователь может отключить в обоих местах.
- Если у кандидата ожидаемый M+1/M+2 ≥ 3× локального шума, а сателлит
  отсутствует — сильный штраф.
- Если сателлит есть, но интенсивность отличается от ожидаемой — штраф
  пропорционален относительному отклонению.
- Если оба кандидата выше/ниже порога, изотопный фильтр для данного пика
  не решает; решение принимают другие признаки.

## 7. Конфликты

- Наложение пиков штрафуется всегда (статья «наложение»).
- Дополнительный конфликтный штраф — только если у одной из серий нет
  предыдущей ступени.
- Серия без пропуска дополнительного конфликтного штрафа не получает:
  наложение уже учтено.
- При `max_gaps = 0` конфликтный штраф отдельно не начисляется, но
  наложение остаётся.

## 8. FDR и значимость

Остаются внутренними параметрами для оптимизации. В пользовательском
GUI/CLI не показываются и не влияют на рабочую выдачу.

## 9. Статус реализации

Реализовано:

- новые значения по умолчанию (max_gaps=0, require_first_step=False);
- запрет серий при отсутствии первых трёх ступеней;
- удаление min_series_length, drop_ambiguous, trim_to_confirmed_last;
- O-лимит, confirmed_length, ambiguous_length, confidence,
  display_length, step_details;
- штрафы source overlap, O-excess, isotope, gap, conflict;
- per-step RAW-метрики: persistence, shape, multi → poor_resolution;
- профиль интенсивностей (скачок и корреляция) как штраф;
- profile-разрешение наложений: 3 скана, S/N ≥ 3, FWHM 1e-4–0.05,
  объединённое окно, правило `k_obs ≥ 1 + n_src`;
- изотопный порог 3× шума, мягкий сильный штраф, iso_dev и попарное
  правило 3× для двух измеримых кандидатов;
- NOM-ratio и NOM-DBE как переключатели GUI/CLI (химическая DBE всегда);
- отчёт N_COOH/N_OH — confirmed-длина, N_*_display — 3(5),
  N_*_details — причины; двойной клик в GUI показывает причины;
- удаление вычитания исходника из pipeline/UI/CLI;
- удаление persistence-статуса.

Осталось:

- калибровка весов штрафов на реальных данных;
- проверка profile-разрешения на полном F16 (сейчас покрыто unit-тестом
  `profile_peaks` и синтетическими сериями).
