# Руководство пользователя NOM-HRMS FGA

> Версия: 0.9.0 | Последнее обновление: октябрь 2026

### Приоритет точности в поиске серий

Проект придерживается принципа: **честное «COOH ≥ 1» лучше, чем «COOH ≥ 4»,
полученное попаданием в ложный пик**. Поэтому по умолчанию включены:

* шумоподавление спектров дериватизации;
* вычитание исходника из дериватизатов (модель «один к одному», окно 2 ppm);
* окно поиска серий 2 ppm (вместо 5 ppm);
* требование подтверждённой **первой ступени** серии: если монодериватизированный
  продукт не найден, серия не засчитывается вовсе (ступени 2, 3, 4 без первой —
  почти всегда случайные совпадения).

Следствие: часть соединений остаётся без серий («нет данных»), а средние N_COOH /
N_OH приходят к физиологичным значениям (2–4 для фульвокислот). Если для образца
нужна большая чувствительность, окна можно ослабить вручную (`--ppm-tol`,
`--subtract-ppm`, `--no-require-first-step`), понимая риск ложных срабатываний.

### Шумоподавление дериватизатов и вычитание исходника

По умолчанию производные спектры (CD3 / CD3CO) **не** шумоподавляются: пики
продуктов низкоинтенсивные и могут потеряться вместе с шумом. Для сложных образцов
доступны две опции:

* **«Шумоподавление спектров дериватизации»** (`--denoise-derivatives`) —
  применяет тот же порог шума, что и к исходнику;
* **«Вычитать исходник из дериватизатов»** (`--subtract-source`) — исключает из
  производных спектров пики, совпадающие по m/z с исходником: это
  непрореагировавшие соединения, а не продукты. Правило — **один к одному**:
  каждый пик исходника вычитает не более одного (ближайшего по массе) пика
  дериватизата, поэтому один и тот же пик не вычитается дважды. Совпадение
  ищется **только по массе** (интенсивности не сравниваются), окно задаётся
  ключом `--subtract-ppm` (по умолчанию 5 ppm).

В лог печатается, сколько пиков удалено, например:
`Вычитание исходника (dmet): удалено 32 из 405 пиков (7.9%) при 5 ppm`.

Обе опции по умолчанию выключены до валидации на реальных наборах (см. ADR-0008):
вычитание может убрать и настоящую ступень серии, если продукт случайно совпал по
массе с пиком другого соединения.

### Пропуски в сериях дериватизации

Правило по умолчанию: **в серии допускается не более одного пропуска** (пропущенная
ступень внутри найденного ряда). При исчерпании бюджета серия обрывается на
последней надёжно найденной ступени, поэтому уже найденные группы не теряются, а
завышения ``N_COOH`` / ``N_OH`` из-за «дырявых» рядов не происходит.

Настроить можно в GUI (поле «Пропусков в серии (0 = без пропусков)») или в CLI:

* ``--max-gaps 0`` — пропуски запрещены (серия обрывается на первом пропуске);
* ``--max-gaps 1`` — правило по умолчанию;
* ``--max-gaps N`` — разрешить до N пропусков.

Устаревшие ключи ``--allow-gaps`` / ``--no-allow-gaps`` по-прежнему принимаются:
``--no-allow-gaps`` равнозначен ``--max-gaps 0``.

## 1. Установка

### Windows — .exe (рекомендуется)

1. Скачайте `NOM_HRMS_FGA.exe` со страницы [Releases](https://github.com/MikhaylenkoVS/NOM-HRMS-FGA/releases)
2. Запустите двойным кликом — установка не требуется
3. При первом запуске Windows SmartScreen может показать предупреждение:
   нажмите **«Подробнее»** → **«Выполнить в любом случае»**

### Windows / macOS / Linux — pip

```bash
pip install git+https://github.com/MikhaylenkoVS/NOM-HRMS-FGA.git
nom-hrms-fga
```

Требуется Python ≥ 3.10. На Linux дополнительно: `sudo apt install python3-tk`.

### Для разработчиков

```bash
git clone https://github.com/MikhaylenkoVS/NOM-HRMS-FGA.git
cd NOM-HRMS-FGA
pip install -e ".[dev]"
python -m src
```

## 2. Подготовка данных

### Формат CSV

Программа принимает три CSV-файла, полученные методом HPLC-HRMS:

| Файл | Описание |
|------|----------|
| **Исходный спектр** | Недериватизированный образец |
| **Дейтерометилирование** | Образец после CD₃-метилирования (–COOH → –COOCD₃) |
| **Дейтероацилирование** | Образец после CD₃CO-ацилирования (–OH → –OCOCD₃) |

### Требования к колонкам

```csv
mass,intensity
100.0518,245030.0
101.0597,123410.5
...
```

- Разделитель: запятая или табуляция
- Колонки: `mass` (или `m/z`) и `intensity`
- Массы в Dalton, интенсивности в условных единицах

### ThermoRAW (Windows, опционально)

При наличии `.raw`-файлов программа автоматически усреднит спектры
по заданному RT-диапазону. Требуется установка Thermo RawFileReader DLL
(см. [инструкцию](https://github.com/thermofisherlsms/RawFileReader)).

## 3. Запуск анализа

### Загрузка спектров

1. Откройте вкладку **Параметры**
2. Для каждого из трёх спектров нажмите **Обзор** и выберите CSV-файл
3. При необходимости укажите RT-диапазон для `.raw`-файлов

**Режим отрезков RT (экспериментальный).** Исходный спектр можно разбить
по RT на отрезки, но дериватизаты при этом усредняются по всему файлу.
Сопоставление по RT для дериватизатов не выполняется: RT продукта и
исходного соединения может различаться, поэтому возможны ложные совпадения.

### Настройка параметров

| Параметр | По умолчанию | Описание |
|----------|-------------|----------|
| Пресет | — | Набор параметров для типа образца (см. [Пресеты](#5-пресеты)) |
| Относительная ошибка, ppm | 1.0 | Допустимое отклонение массы |
| Денойз | auto (GMM) | Метод шумоподавления: auto, quantile или порог |
| Сила денойза | 1.0 | Множитель порога (1.0–3.0) |
| Диапазоны элементов | из конфига | Минимум/максимум атомов для каждого элемента поиска |
| Изотопный фильтр | выкл. | Учитывать изотопный паттерн M+1/M+2 при выборе формулы |

### Диапазоны элементов

Набор элементов поиска задаётся в `src/configs/constants/formula_search.json`
(ключ `elements`) и по умолчанию включает
**C, H, O, N, S, P, F, Cl, Br, I**. Поля для всех элементов строятся в GUI
автоматически из конфига, поэтому добавление нового элемента не требует правки
интерфейса.

Значения по умолчанию (можно менять прямо в GUI):

| Элемент | Диапазон | Элемент | Диапазон |
|---|---|---|---|
| C | 1–50 | S | 0–5 |
| H | 4–100 | P | 0–5 |
| O | 0–25 | F, Cl | 0–5 |
| N | 0–10 | Br, I | 0–3 |

Дополнительно действуют химические ограничения (из того же конфига):
отношения H/C, O/C, N/C, S/C, P/C и X/C (X — сумма галогенов),
неотрицательный целый DBE и правило чётности валентностей.

> **Ограничения по отношениям — жёсткие.** Они отсекают формулы, а не просто
> понижают их рейтинг. Практическое следствие: при очень узком диапазоне
> углерода (например, C 1–3) достижимая масса ограничена ~135 Да, поэтому на
> спектрах с пиками 200–600 Да назначений не будет — это ожидаемое поведение,
> а не ошибка. Для обычного анализа оставляйте диапазоны по умолчанию.

> **Про скорость.** Кандидаты формул берутся из сжатой базы
> (`data/formula_db`), поэтому расширенные пределы почти не влияют на время:
> полный прогон set_01 — ~11 с. Если файл базы недоступен, включается перебор —
> тогда широкие пределы (например, X/C 0.5) ощутимо замедляют работу
> (до ~4 с на пик при m/z 800).

### Изотопный паттерн

Изотопные данные (массы и природные распространённости) лежат в
`src/configs/constants/isotope.json`. Изотопные проверки **включены по
умолчанию** (галочки на вкладке «Параметры → Фильтры»):

* для каждого кандидата считается теоретическое отношение M+1/M и M+2/M;
* наблюдённые отношения измеряются в исходном спектре (до шумоподавления);
* сильное расхождение даёт штраф, а совпадение M+2 для S/Cl/Br-формул —
  бонус (изотопное подтверждение «нестандартного» состава);
* формулы с S/P/галогенами без изотопного подтверждения проигрывают
  CHNO-варианту в том же ppm-окне (защита от ложных назначений);
* **отсутствие сателлита отклоняет кандидата только тогда, когда этот сателлит
  должен был быть измерим** — предсказанная интенсивность сателлита
  сравнивается с уровнем шума спектра (нижний процентиль интенсивностей
  исходного пиклиста, ключ `noise_floor_quantile`). Если сателлит ниже уровня
  шума, жёстких выводов не делается: это отсутствие данных, а не отсутствие
  сателлита. Особенно важно для F и I — у них своего характерного паттерна нет.

**Статус изотопного подтверждения.** Для каждого назначенного пика в отчёте
есть две колонки:

* `iso_status` — `confirmed` (предсказанный паттерн подтверждён),
  `inconsistent` (измеримый сателлит отсутствует или расходится) или
  `uninformative` (сателлитов не измерить: данных недостаточно);
* `iso_halogen_unconfirmed` — `True`, если в формулу вошёл галоген, но
  изотопного подтверждения нет. Такие формулы не «доказаны»: их следует
  проверять отдельно.

**Изотопные варианты.** При включённой галочке «Искать изотопные варианты»
для каждой найденной формулы ищутся её варианты (`13C`, `2H`, `15N`, `17O`,
`18O`, `33S`, `34S`, `37Cl`, `81Br`, …): ожидаемая m/z сравнивается с пиками
исходного спектра, а измеренное отношение интенсивностей — с теоретическим.
Совпавшие варианты попадают в колонку `iso_variants` отчёта, например
`13C 0.077/0.076` (измеренное/теоретическое).

**Изотопные сателлиты.** Пик, который тяжелее другого пика на Δ и чьё отношение
интенсивностей совпадает с теоретическим, помечается как сателлит
(колонки `iso_satellite_of`, `iso_satellite_label`) и **не попадает в отчёт**
как самостоятельное соединение.

**Список изотопов.** Кнопка **«📋 Список изотопов…»** открывает отдельное окно с
таблицей: элемент, изотоп, масса (Да), природная распространённость (%). Там же
видно, что P, F и I моноизотопны (один изотоп).

### База формул: что ставится и что можно выбрать

**Инсталлер ставит базовую базу CHNOSP всегда** — выбор «скачать или не
скачать» не предлагается: она занимает десятки мегабайт и ускоряет работу
кратно, выключать её пользователю незачем.

| Вариант | Объём | Весь пайплайн | Ускорение | В инсталлере |
|---|---|---|---|---|
| **CHNOSP** — 79 576 593 формулы (C, H, N, O, S, P) | **36.2 МБ** (+2.5 МБ манифест) | **33.5 с** | **×19.4** | ставится всегда |
| **CHNOSPHal** — 2 633 587 551 формула (плюс F, Cl, Br, I) | ~0.55 ГБ (оценка) | уточняется (~25 с, оценка) | ~×25 (оценка) | не предлагается, пока объём несопоставим |

Замеры — по **всему пайплайну** (загрузка → шумоподавление → назначение формул →
поиск серий → итоговая таблица) на `set_01` (316 пиков), инструмент
`tools/diagnostics/measure_db_variants.py`. Перебор без базы: 347 с (×1). Сравнивать именно так важно: стадии
загрузки, шумоподавления и экспорта от базы не зависят, поэтому «выигрыш на
назначении» больше, чем «выигрыш в целом» (для справки: назначение формул
отдельно — ~7 с против ~142 с, ×20).

**CHNOSPHal отдельно от exe.** CHNOSPHal (~538 МБ) не входит в бинарник.
В GUI кнопка **«📦 База формул…»** показывает, какие базы установлены, и
предлагает **скачать CHNOSPHal** в пользовательский каталог
(`platformdirs.user_data_dir("NOM-HRMS-FGA")`). После перезапуска программа
подхватит её автоматически как более быстрый вариант. Загрузка идёт с
GitHub Releases (`release_manifest.json` + файлы `.fdb/.idx/.manifest.json`),
с проверкой SHA-256 и атомарной установкой.

**Как программа выбирает.** Реестр вариантов — `src/core/formula_db/_variants.py`.
Если установлены обе базы, берётся более быстрая (CHNOSPHal). Принудительно:

```bash
set NOM_FORMULA_DB=chnosp     # только базовую
set NOM_FORMULA_DB=chorsphal  # только с галогенами
set NOM_FORMULA_DB=none       # без базы (перебор, для диагностики)
```

Посмотреть, что установлено, что будет использовано и что сделает инсталлер:

```bash
python -m src.cli --db-variants
```

В GUI то же самое показывает кнопка **«📦 База формул…»** (вкладка «Параметры»).
Скачанные базы кладутся в пользовательский каталог; вручную их по-прежнему
можно положить в `data/formula_db` (в собранном `.exe` —
`_internal/data/formula_db`).

### Скорость назначения и сжатая база формул

Кандидаты формул берутся из сжатой базы `data/formula_db/*.fdb`
(79 576 593 формулы CHNOSP, 0.1 Да-бины) — это в разы быстрее перебора: полный
прогон set_01 занимает ~11 с вместо ~66 с. Галогены добавляются слоем
подстановок: для каждой подстановки Δ масса «родителя» ищется в окне
`центр − Δ ± допуск`, нужные бины базы читаются пакетно и один раз.

**Сколько комбинаций проверяется.** Перебор всегда начинается с
**наименьших количеств каждого отдельного галогена**: сначала `F1`, `Cl1`,
`Br1`, `I1`, затем двух-атомные комбинации, затем трёхатомные и так далее.
При равном числе атомов приоритетнее «концентрированные» варианты: `F5` и
`Cl4F` важнее, чем `F2ClBrI`.

* какие комбинации вообще допустимы — определяют пределы по галогенам
  (например, при `Cl ≤ 5` и `Br ≤ 3` комбинация `Br4` невозможна);
* по умолчанию включена галочка **«Проверить все комбинации галогенов
  (значительно замедляет обработку)»**, то есть проверяются все допустимые
  комбинации;
* если снять галочку, проверяются только первые 16 комбинаций по приоритету.

Кнопка **«⚙ Настройки поиска по галогенам…»** открывает отдельное окно: там
задаются пределы по каждому галогену и общий предел атомов, показывается
живой предпросмотр («будет проверено N из M допустимых комбинаций» и список
верхних комбинаций), а сверху — та самая галочка полного перебора.

**Предупреждение перед анализом (сейчас показ выключен).** Механика предупреждения сохранена в коде и включается флагом `halogen_search.show_warning`; по умолчанию выключена, так как замеренное замедление оказалось незначительным (см. таблицу ниже). Работает она так: если проверяемых комбинаций заметно больше
базовых 16 (порог `warn_from = 21`), перед запуском выводится предупреждение:
сколько комбинаций будет проверено из допустимых, ориентировочное замедление
назначения формул и где изменить настройку. Замедление берётся из измеренной
таблицы `halogen_search.slowdown_table` (замер на set_01/set_02,
`tools/measure_halogen_slowdown.py`):

| Комбинаций | Замедление |
|---|---|
| 16 (база) | ×1.00 |
| 20 | ×1.05 |
| 30 | ×1.10 |
| 40 | ×1.20 |
| 60 | ×1.35 |
| 80 | ×1.45 |
| 100 | ×1.65 |
| все допустимые | ×1.80 |

Проверено и на реальном наборе (SRFA, три RAW-файла, 1177 пиков): полный пайплайн 18.1 с при 16 комбинациях против 26.5 с при полном переборе (×1.46); на уровне назначения формул — 5.6 против 8.0 мс/пик (×1.4).
Историческая оценка «×10» относилась к включению галогенов при переборе **без базы формул** (v0.8.0: 2.7 → 27.2 мс/пик на том же реальном спектре); с базой формул то же включение стоит ×2.

Ориентиры: полное назначение формул на set_01 занимает ~3.7 с при 16
комбинациях и ~6.7 с при полном переборе (измерено там же). Если файл базы
недоступен, программа автоматически переходит на перебор (медленнее, но
корректно).

Изотопные данные доступны и через Python API:

```python
from src.core.spectrum._isotopes import variants, find_isotope_variants

variants({"C": 7, "H": 6, "O": 2, "Cl": 1})
# [{'label': '37Cl', 'delta_mass': 1.997, 'ratio': 0.32, …}, …]
```

## 4. Интерпретация результатов

### Вкладка «Спектры»

Отображает три спектра (исходный, дейтерометилированный, дейтероацилированный)
с разметкой пиков. Для каждого пика показана назначенная брутто-формула.

### Вкладка «Результаты»

Таблица со столбцами:

| Колонка | Описание |
|---------|----------|
| `mass` | Наблюдаемая m/z |
| `intensity` | Интенсивность пика |
| `brutto` | Назначенная брутто-формула |
| `N_COOH` | Число карбоксильных групп |
| `N_OH` | Число гидроксильных групп |
| `missing_dmet` | Отсутствует в дейтерометилированном спектре |
| `missing_dacet` | Отсутствует в дейтероацилированном спектре |

### Диаграмма Ван-Кревелена

Вкладка **Van Krevelen** — график H/C vs O/C для всех идентифицированных
соединений. Области графика соответствуют классам NOM:

- Липиды (H/C 1.5–2.0, O/C 0–0.3)
- Белки/пептиды (H/C 1.5–2.0, O/C 0.3–0.6)
- Лигнины (H/C 0.7–1.5, O/C 0.1–0.7)
- Танины (H/C 0.5–1.5, O/C 0.6–1.0)
- Конденсированные ароматические соединения (H/C 0.3–0.7, O/C 0–0.7)

### Гомологические серии

Вкладка **Серии** показывает цепочки соединений, отличающихся на CH₂-группу.

## 5. Пресеты

Пресет — набор параметров, оптимизированный под тип образца.

| Пресет | Рекомендуется для | Особенности |
|--------|-------------------|-------------|
| `soil` | Почвенные образцы | Широкий диапазон масс, высокое разнообразие |
| `peat` | Торф | Низкая степень ароматизации |
| `coal` | Уголь | Высокая ароматичность, низкий H/C |
| `water` | Водные образцы | Низкая концентрация, узкий диапазон масс |

Выберите пресет на вкладке **Параметры** — все настройки заполнятся автоматически.

## 6. Частые ошибки и их решение

### «Python не найден» при установке через pip

Переустановите Python с официального сайта [python.org](https://python.org),
отметив галочку **«Add Python to PATH»**.

### «Неверный формат файла»

Убедитесь, что CSV содержит колонки `mass` (или `m/z`) и `intensity`.
Разделитель — запятая или табуляция.

### «Нет результатов» после анализа

Возможные причины:

- Неправильно выбран пресет — попробуйте другой
- Слишком узкий диапазон масс — проверьте параметры `min_mass` / `max_mass`
- Низкое качество данных — увеличьте `rel_error_ppm` до 2.0–3.0

### «RawFileReader not available»

Ошибка возникает при попытке загрузить `.raw`-файл без установленных DLL.

- Убедитесь, что 4 файла RawFileReader DLL находятся в папке `thermo/`
- Проверьте, что установлен `pythonnet`: `pip install pythonnet>=3.0`

### Приложение не запускается на Linux

Установите tkinter: `sudo apt install python3-tk`.
