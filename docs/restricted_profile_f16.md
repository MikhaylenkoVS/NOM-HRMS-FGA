## 0. Термины

Чтобы обозначения ниже читались без расшифровки:

| Термин | Что означает |
|---|---|
| **Якорь** | исходный пик с назначенной формулой; для него строится серия. |
| **Позиция** | гипотеза «якорь i, степень n»: ожидаемая m/z μ=m_0+nΔ. Это не пик, а место, где должен быть продукт. |
| **h** | полуширина окна допуска в Да: проверяем [μ-h,μ+h]. |
| **n_deriv** | сколько пиков дериватизата попало в [μ-h,μ+h]. |
| **n_src** | сколько пиков исходника попало в то же окно [μ-h,μ+h]. |
| **`present`** | profile подтвердил отдельный пик дериватизата (при наличии мешающего исходного пика). |
| **`chain`** | шаг был `unconfirmed`, но подтверждён следующим `present`-шагом без наложения. |
| **`unconfirmed`** | в объединённой области разрешён ровно один пик при ожидании k_src исходных; продукт нельзя отличить от мешающего пика (наложение). |
| **`unreliable`** | profile не разрешает даже ожидаемые исходные пики, либо исходных сигналов несколько; область слишком сложная, решение невозможно. |
| **`absent`** | в окне нет пика дериватизата. |
| **Надёжный пик** (`reliable`) | ровно один пик дериватизата (n_deriv=1) **и** ноль сигналов исходника (n_src=0). Это определение заказчика; profile для такого случая не вызывается. |
| **Ненадёжный пик** (`ambiguous`) | пик дериватизата есть, но условие `reliable` не выполнено: n_src>0 или n_deriv≠1. |
| **`mean_prefix`** | среднее по **всем якорям** число подряд идущих `present/chain` от n=1 до первого не-`present/chain`. Якоря с нулём входят в среднее; это не средняя длина отобранных серий. |
| **`mean_len_retained`** | средняя длина только тех серий, которые прошли FDR q≤0.05. Знаменатель другой — поэтому 5–6 не противоречит `mean_prefix` 0.3–0.5. |
| **`PPD_deriv`** | число пиков дериватизата в окне позиции (определение заказчика). |
| **`PPD_src`** | число пиков исходника в том же окне. |
| **`PPD_sum`** | PPD_deriv+PPD_src. |
| **`PPD_rev`** | обратная величина: сколько позиций претендуют на один пик дериватизата. В старом отчёте это называлось «PPD≥2»; здесь переименовано, чтобы не путать с `PPD_deriv`. |
| **`strict hard`** | удалить все пики, у которых статус `unconfirmed` или `unreliable`. |
| **`margin hard`** | удалить только пики, которые **явно ближе к исходному B**, чем к μ, с запасом 0.0001 Да. |
| **`soft`** | пики не удалять; серия проходит, если у неё ≤1 `unconfirmed/unreliable` и последний шаг `present/chain`. |
| **Подтверждённая длина** | степень n последнего `reliable`-пика в непрерывном префиксе. |
| **Неподтверждённая длина** | степень n последнего `ambiguous`-пика, если он дальше подтверждённой длины; пишется в скобках. |

## 2. Правило profile

* Если в окно дериватизата μ=m_0+nΔ **не** попадает мешающий
  исходный пик — profile не вызывается; пик в окне считается дериватизатом.
* Если мешающий пик B есть — проверяется объединение
  [min(μ,m_B)-h, max(μ,m_B)+h].
  Считаются разрешённые локальные максимумы (S/N ≥ 3, FWHM 1e-4–0.05 Да).
  * k_obs ≥ k_src+1 → `present`;
  * k_obs=k_src → `unconfirmed`;
  * иначе → `unreliable`.
* `unconfirmed` может подтвердиться следующим шагом (`chain`), если n+1
  `present` и его область без мешающих пиков.
* Серия обрывается на первом не-`present/chain`.
* 3 скана, решение по большинству.

## 3. PPD по определению заказчика

* PPD_deriv — сколько пиков дериватизата попало в [μ-h,μ+h];
* PPD_src — сколько пиков исходника попало в то же окно;
* PPD_sum=PPD_deriv+PPD_src;
* `reliable` — PPD_deriv=1 и PPD_src=0.

## 4. Состав статусов

При n=1 (первый шаг):

| h | Производная | present+chain | unconfirmed | unreliable | absent |

| 0.0003 | CD3 | 20.3 % | 5.7 % | 17.8 % | 56.2 % |
| 0.0003 | CD3CO | 22.4 % | 9.3 % | 15.2 % | 53.1 % |
| 0.0005 | CD3 | 25.6 % | 9.3 % | 22.0 % | 43.1 % |
| 0.0005 | CD3CO | 26.2 % | 14.9 % | 18.8 % | 40.1 % |

По всем степеням (h=0.0003): CD3 present 16.4 %, unconfirmed 3.7 %,
unreliable 11.2 %, absent 67.3 %; CD3CO present 16.0 %, unconfirmed 6.5 %,
unreliable 13.2 %, absent 62.4 %.

`unconfirmed` и `unreliable` — это два разных отказа:

* `unconfirmed` — **наложение**: в объединённой области разрешён ровно один
  пик, хотя ожидался один исходный + один дериватизат. Нельзя сказать,
  какой из двух перед нами; пик есть, но он не подтверждает продукт.
* `unreliable` — **область не разрешается**: исходных сигналов несколько,
  а profile видит меньше пиков, чем ожидалось, или не видит их вовсе.
  Это не «ложный пик», а «мы не можем принять решение».

`absent` — в окне дериватизата вообще нет пика. Именно `unreliable` даёт
основной вклад в потери при строгом вычитании.

## 5a. Политика подтверждённой/неподтверждённой длины

Это отдельная политика, не совпадающая с FDR-длиной. Алгоритм для якоря:

1. Идём по n=1,2,…, пока в окне есть пик дериватизата
   (n_deriv≥1). Первый n_deriv=0 — обрыв, дальше не идём.
2. Шаг **надёжный** (`reliable`), если n_deriv=1 и n_src=0.
3. Шаг **ненадёжный** (`ambiguous`), если n_deriv≥1, но условие
   выше не выполнено (n_src>0 или n_deriv≥2).
4. **Подтверждённая длина** — максимальный n среди `reliable`.
5. **Неподтверждённая длина** — максимальный n среди `ambiguous`, если
   он больше подтверждённой; иначе 0 (пишется в скобках, например `2 (3)`).

Пример: n=1 reliable, n=2 ambiguous, n=3 reliable →
подтверждённая 3, неподтверждённая 0. Если n=1 reliable, n=2
ambiguous, n=3 ambiguous → 1 (3).

|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| **0.0003** | 0.442 | 0.075 | 77.1 % | 12.2 % | 2.3 % | 0.454 | 0.107 | 73.4 % | 12.4 % | 1.3 % |
| **0.0005** | 0.709 | 0.163 | 68.3 % | 19.4 % | 5.4 % | 0.694 | 0.231 | 65.4 % | 19.9 % | 3.6 % |
| 0.0008 | 1.036 | 0.311 | 59.0 % | 27.4 % | 9.8 % | 0.980 | 0.416 | 58.0 % | 26.7 % | 7.9 % |

Политика гораздо строже FDR-длины: при 0.0003 Да у 73–77 % якорей нет ни
одного надёжного первого шага, а средняя подтверждённая длина — 0.44–0.45.
Это прямое следствие определения «n_src=0»: любой исходный сигнал в
окне делает пик ненадёжным, даже если профиль разрешает два пика.

## 6. Почему строгий режим так много режет

FWHM в profile на m/z 400–500 — **0.0004–0.0009 Да**. Окна 0.0003–0.0005
сравнимы с FWHM или уже него, поэтому два продукта/пика с разницей
0.0001–0.0005 Да физически не разрешаются: profile видит одну вершину.
По правилу «один пик → unconfirmed» это сразу уводит позицию в
`unconfirmed`, а если рядом несколько исходных пиков — в `unreliable`.

Дополнительная проверка: для `unconfirmed/unreliable` при h=0.0003
наблюдаемый пик **ближе к μ**, чем к ближайшему исходному пику, в
**64 %** случаев (CD3 3 352 из 5 267; CD3CO 4 407 из 6 873). То есть
строгое правило часто выбрасывает вероятный продукт только потому, что
рядом оказался исходный пик, которого в дериватизатном спектре может
вообще не быть.

## 8. Выводы и рекомендация

1. **Ограниченный assign работает**: медиана кандидатов упала с 79 до 13,
   неправдоподобные формулы ушли. Это удешевляет и стабилизирует
   последующие проверки.
2. **Строгое profile-вычитание слишком агрессивно** для F16: окна
   0.0003–0.0005 Да ниже/на уровне FWHM, поэтому «один пик» — обычная
   ситуация, а не признак ложного продукта. Жёсткий режим удаляет 5 %
   пиков, но 55–75 % серий.
3. **Мягкий режим в текущем виде ещё жёстче** (требует последний шаг
   present/chain и ≤1 проблемного шага). Его нужно ослабить: разрешать
   `unconfirmed` в середине серии, если есть chain или вторая дериватизация.
4. **Лучший практичный hard-фильтр** — удалять только пики, которые
   **явно ближе к исходному B**, с запасом 0.0001 Да: удаляется ~900–1 100
   пиков, сохраняется 91 % / 85 % серий. Это ближе к смыслу «B точно
   мешает», чем удаление всех `unconfirmed`.
5. **`unreliable` не надо удалять**: это «не разрешили», а не «ложный».
   Такие пики нужно оставлять, помечать и не использовать как единственное
   доказательство продолжения серии.
6. **Окно 0.0003/0.0005 Да** имеет смысл только как «строгий режим»; для
   рабочего режима лучше 0.0005–0.0010 Да, но с мягкими статусами, а не с
   удалением.
7. **PPD по определению заказчика** (`PPD_deriv`) при 0.0003 Да равен
   0.213 / 0.242 пика на позицию, при 0.0005 — 0.324 / 0.366. Это в 2.3–2.8
   раза меньше старого 2 ppm (0.539 / 0.687), то есть сужение окна
   действительно снижает число кандидатов. `PPD_rev≥2` (позиций на пик)
   при этом 1.1–2.4 %; это другой показатель, его нельзя сравнивать с
   `PPD_deriv` напрямую.
8. **Политика подтверждённой длины** при 0.0003 Да даёт среднюю
   подтверждённую длину 0.44 / 0.45 и 73–77 % якорей без единого надёжного
   первого шага. Это гораздо строже FDR-длины (медиана 5–6), потому что
   любой исходный сигнал в окне (`n_src>0`) делает шаг ненадёжным. Нужно
   решить, считать ли profile-разрешённые наложения (2 пика) надёжными;
   сейчас по определению `n_src=0` они попадают в `ambiguous`.
9. **Что уточнить в следующей итерации:** (а) разрешать `reliable` при
   `n_src>0`, если profile видит k_src+1 пиков; (б) писать
   неподтверждённую длину всегда, даже если она меньше подтверждённой;
   (в) считать `PPD_deriv` после profile-фильтра и до него — это разные
   величины.

## 9. Ограничения

* Мешающие пики — назначенные исходные пики; непривязанные реальные
  соединения не учитываются.
* Исходный B может отсутствовать в дериватизатном спектре; строгое
  требование k_src пиков тогда завышает `unreliable`.
* 3 скана, majority; при другом выборе сканов статусы могут немного
  меняться.
* F16 — один образец; выводы о 0.0003 vs 0.0005 нужно проверить на
  SRFA/F14 и синтетике с известными связями.
