# Reliability-политика v2 (F16): без FDR и без prefix

Дата: 2026-10-21. Данные: restricted assign (C5–60, H4–120, O1–30, N≤5,
S≤2, P≤1, Cl≤2, F/Br/I=0, NOM-ratio), GMM 2.0, F16.
Скрипт: `tools/diagnostics/reliability_policy_f16.py`.
Артефакты: `D:/Temp/User/reliability_policy_v2_f16.json`,
`reliability_policy_v2_positions.pkl`.

Этот отчёт заменяет разделы 4–5 в `restricted_profile_f16.md`: там остались
старые `unconfirmed/unreliable` и FDR-режимы, которые **не используются**
для валидации.

## 1. Термины

| Термин | Определение |
|---|---|
| **Позиция** | гипотеза «якорь i, степень n» с ожидаемой m/z μ=m_0+nΔ. Не пик. |
| **h** | полуширина окна допуска, Да: [μ-h,μ+h]. |
| **n_deriv** | число пиков дериватизата в [μ-h,μ+h]. |
| **n_src** | число пиков исходника в том же окне [μ-h,μ+h]. |
| **N** | число ожидаемых пиков дериватизатов в области. Сейчас N=1: наложение дериватизата одного вещества на дериватизат другого исключено. |
| **M** | M=n_src — число пиков исходника в той же области. |
| **`reliable`** | n_deriv≥1 и n_src=0; **или** n_deriv≥1, n_src=M≥1 и profile разрешает ≥ N+M пиков. |
| **`ambiguous`** | n_deriv≥1, n_src≥1, profile разрешает <N+M пиков: пик есть, но подтвердить его нельзя из-за неразрешения. |
| **`absent`** | n_deriv=0. |
| **Подтверждённая длина** | максимальный n в непрерывном префиксе (до первого `absent`), для которого шаг `reliable`. `ambiguous` на промежуточных шагах допустимы. |
| **Неподтверждённая длина** | максимальный `ambiguous` n, если он больше подтверждённой; пишется в скобках, например `2 (3)`. |
| **PPD_deriv** | среднее число пиков дериватизата в окне позиции. |
| **PPD_src** | среднее число пиков исходника в том же окне. |
| **PPD_sum** | PPD_deriv+PPD_src. |

## 2. Правила

1. Наложение дериватизата одного вещества на дериватизат другого **не
   рассматривается**. Любой пик в окне дериватизата A считается
   дериватизатом A, если в исходном спектре в той же области пиков нет.
   Поэтому n_deriv≥1 и n_src=0 — уже `reliable`, даже если
   пиков дериватизата несколько.
2. Если в области есть M=n_src≥1 исходных пиков, проверяется
   объединение [min(μ,m_B)-h, max(μ,m_B)+h] по profile.
   Разрешено ≥ N+M пиков → `reliable`; меньше → `ambiguous`.
3. `unconfirmed` и `unreliable` больше не различаются: оба означают
   «наличие пика дериватизата невозможно подтвердить из-за неразрешения».
4. Серия идёт по n=1,2,…, пока n_deriv≥1. Первый
   n_deriv=0 — обрыв.
5. Подтверждённая длина — последний `reliable` в этом префиксе. Проблемных
   шагов до него может быть сколько угодно: важно, что все предыдущие
   степени имеют хотя бы один пик.
6. FDR и `prefix` в этих тестах не используются. FDR по построению
   выбирает более длинные серии; его можно применять только как
   оптимизируемый параметр (минимизация длины при q=0.05), не как
   валидированную оценку.

| h, Да | CD3 ср. подтв. | CD3 ср. неподтв. | CD3 подтв.=0 | CD3 ≥2 | CD3 ≥4 | CD3CO ср. подтв. | CD3CO ср. неподтв. | CD3CO подтв.=0 | CD3CO ≥2 | CD3CO ≥4 |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| **0.0003** | 0.442 | 0.075 | 77.1 % | 12.2 % | 2.3 % | 0.454 | 0.106 | 73.4 % | 12.4 % | 1.3 % |
| **0.0005** | 0.710 | 0.162 | 68.2 % | 19.5 % | 5.4 % | 0.694 | 0.230 | 65.3 % | 19.9 % | 3.6 % |
| 0.0008 | 1.045 | 0.301 | 58.6 % | 27.7 % | 9.9 % | 0.984 | 0.413 | 57.7 % | 26.8 % | 7.9 % |
| 0.0010 | 1.237 | 0.395 | 53.8 % | 32.1 % | 12.7 % | 1.134 | 0.534 | 53.9 % | 29.9 % | 10.1 % |

Пример чтения: `2 (3)` означает, что последний надёжный пик — степень 2,
а последний ненадёжный — степень 3. Это **не** «2 + 3 шага»: обе цифры —
степени (позиции) на одной цепочке, а не количества шагов.

Почему `0.442 + 0.075` не равно `1.871`:

* `1.871` — среднее **число подряд идущих шагов** (любых: reliable или
  ambiguous) по якорям, где есть хотя бы один шаг.
* `0.442` — средняя **степень последнего reliable**-шага; это длина, а не
  количество reliable-шагов.
* `0.075` — средняя **степень последнего ambiguous**-шага, и только если
  она больше степени последнего reliable. Это «хвост», а не все
  ambiguous-шаги.
* Другой знаменатель: `1.871` — только по якорям с шагами (8 716 из
  32 811), а `0.442` и `0.075` — по всем якорям, включая нули.

Корректное разложение — по **количеству шагов**, а не по степеням:

| Величина | CD3 все | CD3 с шагами | CD3CO все | CD3CO с шагами |
|---|---:|---:|---:|---:|
| всего шагов (prefix) | 0.497 | 1.871 | 0.539 | 1.646 |
| reliable-шагов (count) | 0.382 | 1.438 | 0.387 | 1.184 |
| ambiguous-шагов (count) | 0.115 | 0.433 | 0.151 | 0.462 |
| подтверждённая длина (степень) | 0.442 | 1.663 | 0.454 | 1.387 |
| ambiguous-хвост (степень) | 0.075 | 0.281 | 0.106 | 0.325 |

Видно, что `0.382 + 0.115 = 0.497` и `1.438 + 0.433 = 1.871`: это и есть
разложение общего числа шагов. Степени `0.442` и `0.075` складывать нельзя.

Пример: шаги `R A R A` (R — reliable, A — ambiguous), обрыв после 4.
Всего шагов 4; подтверждённая длина 3 (последний R); ambiguous-хвост 4
(последний A). Пара `3 (4)` означает «последний надёжный — 3, последний
ненадёжный — 4», а не 7 шагов.

## 5. Главные наблюдения

1. **Профильное подтверждение N+M почти не меняет результат при узких
   окнах.** По сравнению с правилом «n_deriv=1, n_src=0»,
   добавка `reliable` за счёт profile:
   * h=0.0003: +10 (CD3) и +11 (CD3CO);
   * h=0.0005: +67 и +36;
   * h=0.0010: +1 177 и +625.
   Причина — FWHM 0.0004–0.0009 Да на m/z 400–500: два пика с разницей
   0.0001–0.0005 Да не разрешаются, profile видит одну вершину.
2. **Основной ограничитель — n_src>0, а не число пиков дериватизата.**
   При 0.0003 Да `reliable` 17.3 / 18.0 %, `ambiguous` 4.0 / 6.3 %,
   `absent` 78.7 / 75.8 %. То есть у большинства позиций либо нет пика,
   либо рядом есть исходный сигнал, который не разрешается.
3. **Ослабление soft-правила не помогло само по себе.** Разрешены любые
   проблемные шаги, но подтверждённая длина всё равно 0.44 / 0.45 при
   0.0003 и 1.24 / 1.13 при 0.0010. Причина: надёжных шагов слишком мало,
   чтобы длина росла.
4. **Более широкое окно увеличивает и reliable, и ambiguous.** При
   0.0010 Да reliable 32.9 / 32.2 %, но ambiguous 19.1 / 27.6 %; при
   0.0005 — 24.1 / 23.9 % и 8.2 / 12.6 %. Компромисс между «найти пик» и
   «не подтвердить ложный» здесь не автоматический.
5. **FDR не использовался.** Все числа выше — по всем позициям/якорям, без
   отбора по q. Это важно: предыдущие 5–6 шагов у значимых серий были
   следствием FDR-отбора длинных цепочек.

## 6. Ограничения

* n_src считается по всем пикам исходного спектра после GMM 2.0,
  включая непривязанные; это консервативно.
* Profile — 3 скана, majority; при другом выборе сканов статусы могут
  немного меняться.
* N=1: наложение дериватизатов разных веществ исключено. Если позже
  разрешить, правило N+M нужно проверять отдельно; при N>1
  подтверждение N пиков не говорит, какой из них какому веществу
  принадлежит.
* F16 — один образец; перед переносом на SRFA/F14 нужна проверка на
  синтетике с известными связями.
