# Mass Spec Report Writer — генератор научных отчётов

Генерирует текст для научной публикации (статья ACS, отчёт, диссертация) на
основе результатов обработки спектров конвейером NOM-HRMS-FGA. Двухслойный
вывод: (1) краткое объяснение в чате, (2) файл `.md` для дальнейшего
редактирования.

## Когда активировать

- После успешного `run_pipeline(test_mode=True)` или прогона в GUI.
- При запросе пользователя: «напиши экспериментальную секцию», «сделай
  описание метода», «подготовь раздел Results», «сравнение с эталоном».
- При подготовке релиза (v0.5.0 и далее) — для обновления `CODE_AVAILABILITY.md`.

## Источники данных для отчёта

| Данные | Откуда брать |
|--------|-------------|
| Версия программы | `pyproject.toml` → `version` |
| Параметры запуска | `pipeline.json` → `run_pipeline_defaults` или пользовательские |
| Моноизотопные массы | `chemistry.json` → `monoisotopic_masses` |
| ΔCD3, ΔCD3CO | `chemistry.json` → `derivatization_shifts` |
| Диапазоны элементов | `pipeline.json` → `formula_search.ranges` |
| Пороги DBE, H/C, O/C, N/C | `pipeline.json` → `formula_search` |
| Метрики качества | `TestSetResult`: denoise_recall, assign_recall, wrong_ratio |
| Число молекул/пиков | `PipelineStats` / `TestSetResult` |
| Ван-Кревелен | `src/core/van_krevelen.py` → `NOM_REGIONS` |
| Структуры-кандидаты | `src/core/fragments.py` → `FRAGMENT_LIBRARY`, `FUNCTIONAL_GROUPS` |
| Эталонные молекулы | `data/ref_data/ref_molecules_all_pubchem_filtered.csv` |

## Структура выходного файла (Markdown)

Генерировать файл в `docs/reports/YYYY-MM-DD-pipeline-report.md`:

### 1. Заголовок и мета-информация

```markdown
# NOM-HRMS-FGA: отчёт обработки спектров

> **Дата:** DD.MM.YYYY
> **Версия ПО:** vX.Y.Z
> **Набор данных:** set_01 (синтетический) / пользовательский
```

### 2. Параметры метода

- Режим ионизации: [M–H]⁻
- Диапазон масс: XXX–YYY Da
- Ppm-допуск (assign): X.X ppm
- Ppm-допуск (series): X.X ppm
- Элементы: C (X–Y), H (X–Y), O (X–Y), N (X–Y)
- Жёсткие фильтры: DBE ≤ XX, H/C ≤ X.X, O/C ≤ X.X, N/C ≤ X.X
- Шумоподавление: intensity=X / force=X / quantile=X
- Изотопный фильтр: включён/выключен

### 3. Результаты

- Загружено пиков (original): N
- После шумоподавления: N (recall = X.XX)
- Назначено формул: N (recall = X.XX)
- Найдено –COOH серий: N (совпадений: N, ошибочных: N, ratio = X.XX)
- Найдено –OH серий: N (совпадений: N, ошибочных: N, ratio = X.XX)

### 4. Химический анализ

- Распределение по областям Ван-Кревелена (число формул в каждой области).
- Диапазон –COOH: min–max, медиана.
- Диапазон –OH: min–max, медиана.
- Преобладающие классы соединений.

### 5. Сравнение с эталоном (для синтетических наборов)

- Сколько молекул из эталона найдено.
- Ложноположительные: какие формулы назначены ошибочно.
- Ложноотрицательные: какие молекулы пропущены.

## Правила генерации текста

### Научный стиль

- Безличные конструкции: «было назначено…», «спектр обработан…»
- Латинские названия: _N_, _m/z_, etc.
- Химические формулы: CₓHₓOₓNₓ (Unicode-нижние индексы), [M–H]⁻.
- Ppm всегда с одной цифрой после запятой: 1.0 ppm, 0.5 ppm.
- Массы: X.XXXX Da.

### Что НЕ писать

- «Программа работает отлично» → «Алгоритм показал recall XX.X%»
- «Много пиков» → «Загружено N пиков в диапазоне m/z XXX–YYY»
- Субъективные оценки без данных.

### Code Availability (по стандарту ACS)

Формат из `CODE_AVAILABILITY.md`:
- Software name
- Description (1–2 предложения сути метода)
- Repository URL
- Version / Tag / Release date
- License (GPL-3.0)
- Programming language / Runtime
- Installation command
- Hardware requirements (none special)
- Dependencies (numpy, pandas, matplotlib, rdkit)

## Двухслойный вывод

### Слой 1: в чат (кратко)

После прогона вывести в чат структурированную сводку (заголовки + ключевые
цифры). Формат: Markdown, готовый к копипасте.

### Слой 2: файл для публикации

Сохранить в `docs/reports/`. Имя файла: `YYYY-MM-DD-<краткое-описание>.md`.
Файл открывается для редактирования (пользователь дописывает обсуждение,
добавляет ссылки на литературу).

## Алгоритм генерации

1. **Собрать параметры:** из `PIPELINE` + `CHEM` + пользовательского ввода.
2. **Собрать метрики:** из `PipelineRunResult.stats` / `TestSetResult`.
3. **Сгенерировать черновик** в чат — спросить пользователя, что скорректировать.
4. **После подтверждения** — записать файл в `docs/reports/`.
5. **Проверить** — все числа из pipeline/тестов, нет выдуманных данных.

## Проверочный список

- [ ] Все числовые значения взяты из `CHEM`, `PIPELINE`, `TestSetResult` — не выдуманы.
- [ ] Химические формулы в Unicode (нижние индексы), а не LaTeX (если только не для журнала).
- [ ] Массы в Da, ошибки в ppm, интенсивности в условных единицах.
- [ ] Указана версия программы из `pyproject.toml`.
- [ ] Для синтетических данных: указан номер набора (set_01..set_05).
- [ ] Code Availability секция соответствует `CODE_AVAILABILITY.md`.
- [ ] Файл сохранён в `docs/reports/`.
